用闭包组成可读的数据转换

map、filter 是熟悉的入口。接下来关注 Swift 的类型推断、尾随闭包和生命周期，而不是只把箭头换成花括号。

前置：06 写出调用点清晰的函数

本课的一个成果实现清理、筛选、排序的标题搜索流水线，并解释闭包捕获与逃逸。

从完整签名读懂简写

闭包是可以保存与传递的功能块。完整写法由参数、返回类型、in 和函数体组成；上下文足够时，参数类型和 return 可省略，还可用 $0 指第一个参数。简写的目标是让意图更清楚，嵌套多层时应恢复有意义的参数名。尾随闭包只是调用语法，不意味着异步执行。

let matches: (String) -> Bool = { title in
    title.localizedCaseInsensitiveContains("swift")
}
let titles = ["Swift 6", "UIKit"]
print(titles.filter(matches))
// 相同意图的尾随闭包：
print(titles.filter { $0.localizedCaseInsensitiveContains("swift") })

每一步只承担一个转换职责

map 将每个元素映射为新元素；filter 保留符合谓词的元素；compactMap 把映射结果中的 nil 去掉；reduce 汇总；sorted 返回排好序的新数组，sort 修改原数组。先拆成中间变量看类型，再组合成链式表达式，比写一大串之后猜编译错误更有效。这里仅处理短标题，不需要为每次分配提前引入复杂的 lazy 抽象。

public func searchableTitles(_ titles: [String], matching query: String) -> [String] {
    titles
        .map { $0.trimmingCharacters(in: .whitespacesAndNewlines) }
        .filter { !$0.isEmpty && $0.localizedCaseInsensitiveContains(query) }
        .sorted()
}

闭包捕获不是自动制作快照

闭包可以捕获外部变量；一个可变变量后续被修改，闭包可能看到修改后的值。若要在创建时捕获当时的值，可使用捕获列表。作为函数参数的闭包默认 nonescaping，即不能在函数返回后才调用；若需要存储或稍后执行，参数声明使用 @escaping。逃逸与并发是不同维度：稍后在同一线程执行也属于逃逸；跨隔离域安全将在并发课单独学习。

var query = "Swift"
let live = { query }
let snapshot = { [query] in query }
query = "SwiftUI"
print(live())     // SwiftUI
print(snapshot()) // Swift

先独立完成，再展开参考解法
public func searchableTitles(_ titles: [String], matching query: String) -> [String] {
    let cleaned: [String] = titles.map {
        $0.trimmingCharacters(in: .whitespacesAndNewlines)
    }
    let matched: [String] = cleaned.filter {
        !$0.isEmpty && $0.localizedCaseInsensitiveContains(query)
    }
    return matched.sorted()
}

这个展开版本与仓库的链式版本等价。当前 Foundation 的 localizedCaseInsensitiveContains 对空查询返回 false，因此现有函数会返回空数组。扩展练习：若产品希望空查询显示全部非空标题，将筛选条件明确写成下面形式，并为该规则增加断言；本仓库参考实现暂不改变。

// 可选扩展：把空查询定义为“显示全部”。
.filter { !$0.isEmpty && (query.isEmpty || $0.localizedCaseInsensitiveContains(query)) }

从前端迁移时，留意这些误区

  • $0 不是全局变量；每层闭包都有自己的参数。
  • 捕获可变变量不一定冻结创建时的值；需要快照时明确捕获。
