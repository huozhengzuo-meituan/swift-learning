Observation：共享模型、所有权与隔离

iOS 17 / macOS 14 起，本课程采用 Observation；老项目中的 ObservableObject 仍需读懂，但不混用所有权规则。

前置：27 State 与 Binding：找到唯一数据源

本课的一个成果用环境注入一份可观察偏好，并让设置页通过 Bindable 修改它。

Observable 追踪依赖，MainActor 管理隔离

@Observable 宏为类型生成观察机制。body 读取某个可观察属性，就建立对应依赖；仅传递对象引用不等于读取所有属性。@Observable 本身不保证线程安全，也不会自动把方法放在后台。本例 StudyPreferences 同时标记 @MainActor，说明这些 UI 偏好归主 actor 管理。普通 Sendable 服务值与 UI 模型分开，有利于解释数据跨隔离域时的边界。

@MainActor
@Observable
final class StudyPreferences {
    var showCompleted = true
    var simulateResourceFailure = false
}

创建者用 State 持有，后代按类型读取环境

NativeStudyApp 负责创建偏好，使用 @State 持有它，然后 .environment(preferences) 注入视图树。后代使用 @Environment(StudyPreferences.self) 获得同一实例。环境不是数据库，也不是全局服务定位器；把对象注入特定树，测试或预览便能替换它。忘记为非可选环境依赖注入对象会产生运行时问题，所以每个独立 Preview 都要建立完整依赖。

// App 中：
@State private var preferences = StudyPreferences()
// 根视图：StudyListView().environment(preferences)

// 子视图中：
@Environment(StudyPreferences.self) private var preferences

Bindable 为对象属性产生 Binding

拿到 Observable 引用后，可以直接读写属性；只有 Toggle、TextField 等 API 需要 Binding 时，才需要 @Bindable 投影。示例在 body 内声明局部 @Bindable，随后传 $preferences.showCompleted。这不会再创建一个独立对象，所有读取同一实例该属性的视图都能响应。偏好这里只活在应用会话中，关闭进程后恢复默认值；不要误把观察更新等同于持久化。

var body: some View {
    @Bindable var preferences = preferences
    Form {
        Toggle("Show completed items",
               isOn: $preferences.showCompleted)
    }
}

在 StudyRow 中声明环境依赖，在原日期 Text 外添加条件；所有权继续留在 App。

@Environment(StudyPreferences.self) private var preferences
// body 内：
if preferences.showCreationDate {
    Text(item.createdAt, format: .dateTime.month().day())
}

从前端迁移时，留意这些误区

  • 不要把 Observable 当成自动持久化或线程安全机制。
  • 不要在每个子视图重新创建偏好对象导致状态分叉。

即时自测

Observable 宏自动保证对象能在任何线程被安全修改。
