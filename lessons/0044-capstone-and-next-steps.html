毕业项目：独立完成一个可解释的原生功能

课程材料已经齐备，真正的完成标准是：面对一个新需求，你能独立设计、实现、验证，并讲清限制。

前置：43 处理生命周期、深链接与后台边界

本课的一个成果完成一个从数据建模到双平台验收的垂直功能，并用证据解释设计选择。

一个有边界的真实需求

为 NativeStudy 增加“复习计划”：条目可设定下次复习日期，列表可筛选今日待复习，完成复习后按所选间隔安排下一次。先不接入通知或云同步，聚焦一个可靠的本地功能。需求见 CAPSTONE.md，包含输入、日期边界、持久化与平台行为。

先手画状态和数据流，再写最小模型变化。日期规则要说明时区与“今天”的定义，测试跨日边界。旧数据怎样获得默认值属于迁移设计的一部分；新建数据库测试通过不等于升级不会丢数据。

走完一个垂直切片

第一步实现纯规则并测试；第二步写入存储并证明重开可读；第三步加入表单和列表；第四步处理失败、取消与空状态；最后完成键盘、触控、VoiceOver 与本地化验收。每步保留一个可运行成果，避免同时改模型、并发和导航后失去定位线索。

复用已有模型时保持稳定 ID；跨隔离边界传递值 DTO 或 ID，不随意把某个上下文的持久模型交给后台 actor。把主线程上的工作量控制在能解释的范围。

用评审问题检验理解

请同事或社区评审一个最小问题，例如“这份复习规则在时区变化后应该如何解释”，附最小代码、工具链、预期与实测。Swift Forums 适合语言与并发讨论；Apple Developer Forums 适合平台 API 行为。不要上传用户数据、内部代码和签名凭据。

最终演示不应只有成功路径。主动展示坏输入、保存失败或资源加载失败、重启恢复、两种尺寸和辅助功能操作。尚未拥有的设备如实写为未验证。下一阶段根据你目标岗位选择 UIKit/AppKit 既有项目、系统扩展或发布实践，不必同时学习所有框架。

动手：提交一份可被别人复现的毕业成果

  1. 阅读 CAPSTONE.md，先写需求与状态归属。
  2. 按规则、存储、UI、失败恢复的顺序实现复习计划。
  3. 运行脚本与新增测试，在 iOS 模拟器和 macOS 各走一遍核心旅程。
  4. 填写证据表并完成口头解释题；请 Codex 以代码评审方式检查成果。
验收现象

代码、测试、双平台操作记录与未验证项齐全；能不看答案解释 actor、状态所有者和保存边界。

先独立完成，再展开参考解法

这里不给完整毕业代码，避免把复制当成独立完成。可参考的分解是：ReviewPolicy（纯日期规则）→ StudyItem 的计划字段 → 保存/读取与迁移策略 → 编辑界面 → 待复习查询 → 完成复习操作。验收表给出具体通过标准；卡住时只请求当前一步的提示，完成后将真正掌握的非显然知识记入 learning-records。

从前端迁移时，留意这些误区

  • 不要把参考解法原样重打当成迁移能力。
  • 未验证的真机、签名和上架步骤要明确保留，而非用构建成功代替。
