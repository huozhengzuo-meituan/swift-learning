把前十三课串成一个小但完整的业务核心：可以生成计划、完成任务、显示摘要，并由独立测试证明关键行为。

前置：13 把 JSON 变成可信模型，并保留失败原因

本课的一个成果完成可复用 StudyPlan 模块，并用 Swift Testing 验证边界和重复操作。

先写可观察的契约

本里程碑约定：计划由若干 StudySession 组成；完成一个有效位置返回 true；重复完成仍成功，但计数不重复增加；越界操作返回 false 且不改变计划。计数和总分钟由 sessions 计算，避免多个存储字段同步失败。这些规则不依赖命令行或 SwiftUI，因此应放在 FoundationCore 模块，而不是藏在 UI 事件处理器里。

public struct StudyPlan: Equatable, Sendable {
    public private(set) var sessions: [StudySession]
    public init(sessions: [StudySession]) { self.sessions = sessions }
    public var totalMinutes: Int { sessions.reduce(0) { $0 + $1.minutes } }
    public var completedCount: Int { sessions.filter(\.isCompleted).count }
    @discardableResult
    public mutating func complete(at index: Int) -> Bool {
        guard sessions.indices.contains(index) else { return false }
        sessions[index].complete()
        return true
    }
}

Swift Testing 断言行为，而不是复述实现

使用 import Testing、@Test 与 #expect，不需要继承测试基类。参数化 @Test(arguments:) 能用相同契约覆盖多个输入；throws 断言检查失败类型。先安排数据，再执行操作，最后断言，尤其 mutating 调用适合先保存结果再传给 #expect。测试运行器可能并行执行测试，因此每个测试都创建自己的数据，不依赖前一个测试留下的全局状态。

@Test("重复完成不重复计数")
func repeatedCompletion() {
    var plan = StudyPlan(sessions: [StudySession(title: "Swift", minutes: 25)])
    let first = plan.complete(at: 0)
    let again = plan.complete(at: 0)
    #expect(first)
    #expect(again)
    #expect(plan.completedCount == 1)
}

公共 API 是要维护的承诺

Swift 默认 internal，即同一模块可见；另一个 target 需要使用的声明才加 public。public 类型不会自动让所有成员 public，成员和初始化器需要按意图公开。private(set) 允许读取事实，但把修改集中到方法；这让将来的 UI 无法绕过更新入口。课程测试只 import 公共模块，用用户能调用的 API 检查契约，而不是为访问私有方法强行扩大可见性。

清晰命名也属于正确性：complete(at:) 中 at 说明数字是位置，不是任务 ID。此处位置用于固定 CLI 练习；真正可排序的 UI 列表通常需要稳定 ID，SwiftUI 模块会进一步改进模型。运行器出现 XCTest “0 tests” 后，还需继续看 Swift Testing 汇总；本包实际应报告 13 个测试，通过才算验证完成。

完整可运行里程碑包括 StudyPlan.swift、FoundationLab.swift 的 case 14 和 FoundationCoreTests.swift 的 planMilestone。不要只为了达到覆盖率重复断言同一行；这些测试分别保护边界、幂等与汇总业务规则。

从前端迁移时，留意这些误区

  • 测试完成不等于你已掌握；应能脱离答案重新解释并实现。
  • 不要在测试之间共享可变全局计划，也不要用实现细节替代行为契约。
