用枚举排除不可能的状态

许多界面 bug 来自多个布尔值互相矛盾。先用类型描述合法状态，渲染逻辑就能更直接。

前置：08 用结构体保护业务状态的边界

本课的一个成果用带关联值的枚举表达未开始、进行中和已完成，并穷尽处理。

状态和它的数据应该一起出现

若同时保存 isLoading、isFinished、remaining 和 completedCount，就可能产生“已完成但仍在加载”的组合。Swift enum 能定义互斥分支，并让每个分支携带自己的关联值。active 才拥有 title 与 remainingMinutes；idle 无需伪造空标题；finished 才持有完成数。这与 TypeScript 的可辨识联合类型很接近，但 Swift 的模式匹配由语言直接支持。

public enum StudyState: Equatable, Sendable {
    case idle
    case active(title: String, remainingMinutes: Int)
    case finished(completedCount: Int)
}
let state = StudyState.active(title: "枚举", remainingMinutes: 12)

穷尽 switch 让新增状态被编译器追踪

对自有枚举的 switch 应覆盖每一种 case。当未来新增 paused，原有 switch 会提示缺少分支，帮助找到所有需要处理新状态的位置。若过早写 default，这个反馈会被隐藏。使用 case let 从关联值解包；只关心一个 case 时用 if case，不需要为了取一个字段写整套 switch。

switch state {
case .idle:
    print("尚未开始")
case let .active(title, remainingMinutes):
    print("\(title)：剩余 \(remainingMinutes) 分钟")
case let .finished(completedCount):
    print("完成 \(completedCount) 项")
}
if case let .active(_, remaining) = state { print(remaining) }

原始值、关联值与 Result 各有用途

原始值枚举如 enum Tab: String { case learn, review } 给每个 case 固定的底层表示；关联值则由每次创建实例时提供，不能混为一谈。标准库 Result<Success, Failure> 也是“成功带数据，失败带错误”的枚举模型，Failure 必须符合 Error。需要把结果保存或传递时 Result 有用；同步调用出错通常直接 throws，后面会学习。

本例的剩余分钟依然可能被创建成负数：枚举解决状态组合问题，不会自动验证每个关联值的业务范围。识别类型已经保证什么、还需要校验什么，是比追求“所有东西都类型安全”更实用的工程习惯。

验收现象

新增 case 后 message 的 switch 提示未穷尽；补齐后输出 枚举：已暂停。

先独立完成，再展开参考解法
// 加在 StudyState 的 case 声明中：
case paused(title: String)

// 加在 message 的 switch self 中：
case let .paused(title):
    return "\(title)：已暂停"

// FoundationLab.swift 的 case 9：
let state = StudyState.paused(title: "枚举")
print(state.message)

if case active 只处理进行中，因此新状态时不进入该分支，符合原有语义。无需为了通过编译而把所有 switch 改成 default。

从前端迁移时，留意这些误区

  • Swift enum 不只是 JavaScript 数字常量集合。
  • default 会减少对未来新状态的编译期提醒，使用时要有明确意图。
