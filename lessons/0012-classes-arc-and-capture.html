看见引用共享，打断闭包保留环

原生工程师不仅要知道对象做什么，也要知道它什么时候可以释放。用一条明确的引用链来诊断，而不是给每个闭包机械添加 weak。

前置：11 分清泛型、some 与 any 的类型选择权

本课的一个成果解释 class 的引用身份，并验证弱捕获回调不会让拥有者泄漏。

class 适合需要共享身份的对象

class 赋值共享同一实例；=== 比较身份，== 是否可用及含义取决于 Equatable 实现。let 绑定到一个类实例，只阻止这个绑定指向另一个实例，不冻结对象的 var 属性。final 表示该类不允许被继承，有助于让简单服务或状态对象的扩展边界清楚。初始化器负责建立存储属性，deinit 在实例释放前用于清理自管资源。

let first = StudyCounter()
let second = first
second.increment()
print(first.count)        // 1
print(first === second)   // true
// first 绑定没有改变，但它引用的实例状态改变了。

ARC 计数强引用，环不会自行消失

ARC 管理类实例的引用计数。若 counter 强持有回调，回调又强捕获 counter，就形成 counter → closure → counter；外部变量置 nil 仍不打破内部环。不要把它理解为 JavaScript 垃圾回收器会按可达性自动清除所有孤岛。画出持有关系，再决定哪一条边不该拥有另一个对象。

public final class StudyCounter {
    public private(set) var count = 0
    public var onIncrement: (() -> Void)?
    public init() {}
    public func increment() { count += 1 }
    public func installCallback() {
        onIncrement = { [weak self] in
            self?.increment()
        }
    }
}

weak 允许对象先消失，unowned 需要生命周期证明

weak 不延长实例寿命，对象释放后变成 nil，因此通常是可选引用。回调里 self?.increment() 表示对象还存在才执行；这适合拥有者消失后事件自然失效的场景。unowned 则要求访问时对象一定仍活着，违反会造成运行时错误，不能为了少写问号就选择它。

本例保留回调后再清空 counter，使用独立 weak 观察者验证对象确实释放，并再次调用回调确认安全。并非每个闭包都需要 weak：立即执行的 map/filter 并不天然形成保留环；某些任务必须持有对象直到完成。先讲清所有权和业务寿命，再决定捕获策略。当前 StudyCounter 是同步教学对象，不宣称它能安全跨并发域共享。

先独立完成，再展开参考解法
public func installCallback() {
    onIncrement = { [weak self] in
        self?.increment()
    }
}

仓库中的完整观察函数会保留 callback，并通过 WeakCounter.value 观察是否为 nil。测试不只是断言某次按钮结果，也检查真实所有权关系。临时强捕获实验只用于本地诊断，完成后恢复弱捕获版本。

从前端迁移时，留意这些误区

  • ARC 不等于自动解决所有引用环的追踪式垃圾回收。
  • weak 不是闭包的通用装饰器；先判断闭包是否被保留以及谁应该拥有谁。
