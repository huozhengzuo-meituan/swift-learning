本课的一个成果用 task(id:) 加载条目资源，并阻止旧请求覆盖新页面。

任务身份决定何时重新加载

task(id:) 将任务与视图生命周期和某个 Equatable 值连接。值改变会取消原任务并创建新任务；视图离开后框架也会取消关联任务。本例 ResourceRequest 包含标题、失败开关和重试计数，所以编辑主题、修改设置或点重试都能发起新加载。不要在 body 里写 Task，也不要因为 body 重新求值就认为需要重新请求。较新 SDK 文档给 task 增加了诊断参数，本课程只使用部署基线已有的 id 调用方式。

.task(id: ResourceRequest(
    topic: item.title,
    shouldFail: preferences.simulateResourceFailure,
    retry: retry
)) {
    await loader.load(topic: item.title,
                      shouldFail: preferences.simulateResourceFailure)
}

取消是合作协议，await 后重新检查

取消不是强行终止线程。Task.sleep 和许多异步 API 会响应取消，但业务代码仍应在关键点检查 Task.checkCancellation。ResourceLoader 同时保存 generation：请求开始时取快照，返回后只允许当前代次更新状态。这样即便将来接入不及时响应取消的服务，旧结果也无法覆盖新请求。检查的对象是当前需求，而不只是网络回来了没有。UI 模型仍在 MainActor，await 挂起让出执行机会。

guard !Task.isCancelled else { return } // 尚未开始的旧任务也要忽略。
generation += 1
let request = generation
state = .loading
let resources = try await service.fetch(for: topic, shouldFail: shouldFail)
try Task.checkCancellation()
guard request == generation else { return }
state = .loaded(resources)

状态机让界面互斥，错误与取消区别对待

idle、loading、loaded、failed 使用 enum 表达，不再维护 isLoading、hasError、items 等可能互相矛盾的标志组合。CancellationError 不弹失败提示，因为用户切换条目不是业务故障；真实错误才进入 failed(message)，并提供 Retry。示例延迟固定、数据固定且不用网络，因此可以稳定测试成功、失败、取消。真实网络接入后仍需额外验证 HTTP 状态、解码和超时，不能把 fixture 测试说成网络测试。

enum State: Equatable {
    case idle, loading
    case loaded([ReadingResource])
    case failed(String)
}

验收现象

失败明确可见；切换条目不会把取消当错误；SwiftUI 条目最终显示 SwiftUI 文档资源。

先独立完成，再展开参考解法

两个防线要同时保留：取消检查避免已取消任务提交，generation 避免较早但未及时取消的请求覆盖较新状态。

catch is CancellationError {
    if request == generation { state = .idle }
} catch {
    guard request == generation, !Task.isCancelled else { return }
    state = .failed(error.localizedDescription)
}

单元测试通过受控 actor 等待每次请求真正进入服务，再按逆序返回；不要把一次 Task.yield 当成另一任务已经开始的保证。

从前端迁移时，留意这些误区

  • MainActor 防止同时访问隔离状态，不会自动保证返回顺序符合业务需求。
  • 不要把离线 fixture 的成功误报为真实网络验证。
