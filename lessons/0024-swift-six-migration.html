四个版本维度分开记录

swift --version 显示编译器；Package.swift 第一行决定 manifest API 可用范围；swiftLanguageModes 决定源代码按哪种语言模式检查；platforms 决定部署目标。本包明确 tools 6.0、语言模式 .v6、macOS 14 / iOS 17，当前机器实际编译器为 Swift 6.4。后者不是已经用 Swift 6.0 编译器实测通过的证明。升级 Xcode 也不等于项目已启用 Swift 6 完整数据竞争检查。

// swift-tools-version: 6.0
// Package 的末尾：
swiftLanguageModes: [.v6]
// 查看工具链：终端执行 swift --version

6.2 之后的可接近并发需要看设置

Swift 6.2 引入可配置的默认 MainActor 隔离，以及由 NonisolatedNonsendingByDefault 控制的非隔离 async 调用者隔离语义；这是不同设置，不要合并成“Swift 6 就都在主线程”。.defaultIsolation(MainActor.self) 需要 tools 6.2。SE-0461 的 6.2 语法用 @concurrent 显式表达离开 actor 执行；更新工具链可能继续演进语法，阅读提案时区分已实施内容与修订记录。本包关闭这些 upcoming 选项，保留显式 UI 隔离，便于学习基线。

// 仅为 6.2+ 配置示意；不添加到本课程 tools 6.0 manifest。
swiftSettings: [
    .defaultIsolation(MainActor.self),
    .enableUpcomingFeature("NonisolatedNonsendingByDefault")
]

迁移从所有权与验证开始

旧项目可先在 Swift 5 模式打开完整严格并发警告，再逐模块迁移。每条诊断先回答三件事：谁持有状态、谁会改它、它是否需要跨 actor。优先修正边界与快照，给兼容逃生口写清理由，而非批量加 @unchecked Sendable 或 nonisolated(unsafe)。通过编译只证明静态约束的一部分；本章的 actor 重入、旧请求覆盖与取消收尾仍依赖行为测试。课程已生成不代表你已掌握，应以独立复现这些证明作为阶段完成条件。

先独立完成，再展开参考解法

里程碑答案：预约在 await 前占位，失败时回滚；页面在成功、失败、取消发布前都比较请求版本；流所有者提前退出时显式关闭生产者。结构化任务通过作用域管理生命周期，非结构化任务通过句柄管理。若测试失败，把实际错误和隔离关系带给老师继续分析，不要把测试绿灯写成真机 UI 已验证。

// 从工作区根目录执行：
// swift test --package-path examples/ConcurrencyLab
// swift run --package-path examples/ConcurrencyLab ConcurrencyDemo all
