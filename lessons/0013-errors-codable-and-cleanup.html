把 JSON 变成可信模型，并保留失败原因

网络能返回 JSON，并不代表数据已满足业务条件。本课把“格式能读懂”和“值可以使用”分成两个有测试的步骤。

前置：12 看见引用共享，打断闭包保留环

本课的一个成果区分解码失败和业务校验失败，使用 throws 与 defer 组织成功和失败路径。

throws 让失败路径出现在签名里

函数标注 throws 后，调用者用 try 承认它可能失败；失败可以继续抛给上层，或用 do/catch 恢复。错误必须符合 Error。try? 将失败压成 nil，适合明确不需要原因的情况；try! 宣称不会失败，若判断错误会终止运行。读取外部 JSON 时通常不应该使用 try!。Swift 6 的 typed throws 可以进一步约束错误类型，本课用一个独立校验实验说明适用边界。

public enum PlanError: Error, Equatable {
    case emptyTitle
    case invalidMinutes(Int)
}
do {
    let sessions = try decodePlan(data)
    print(sessions.count)
} catch let error as PlanError {
    print("业务校验失败：\(error)")
} catch {
    print("读取格式失败：\(error)")
}

Codable 解决表示转换，验证解决业务边界

Codable 组合 Encodable 与 Decodable。类型的存储属性都可编码时，编译器通常可以合成实现。JSONDecoder 从 Data 解码为确定类型，因此缺失必填字段或错误字段类型会抛错；它不会自动理解“分钟必须大于零”。本例 JSON 包含 title、minutes、isCompleted 三个键，解码后再检查标题与范围，避免形状合法却语义非法的数据流入界面。

public func decodePlan(_ data: Data) throws -> [StudySession] {
    let sessions = try JSONDecoder().decode([StudySession].self, from: data)
    for session in sessions {
        guard !session.title.trimmingCharacters(in: .whitespacesAndNewlines).isEmpty else {
            throw PlanError.emptyTitle
        }
        guard (1...180).contains(session.minutes) else {
            throw PlanError.invalidMinutes(session.minutes)
        }
    }
    return sessions
}

要适配不同键名可定义 CodingKeys；嵌套结构不同则写自定义解码。不要误以为给 init 参数一个默认值，合成 Decodable 就会自动在 JSON 缺字段时调用那个默认参数。

Swift 6 typed throws：只在错误集合明确时收窄

throws(MinutesError) 约定函数只能抛出 MinutesError。这个同步校验只检查分钟范围，错误集合由同一模块控制，因此调用者可以穷尽处理。do 中若只调用这一种 typed-throws 函数，catch 的 error 保留具体类型；普通 throws 则等价于 throws(any Error)。这些规则自 Swift 6.0 起可用，见 SE-0413。

enum MinutesError: Error { case outOfRange(Int) }

func validatedMinutes(_ value: Int) throws(MinutesError) -> Int {
    guard (1...180).contains(value) else {
        throw MinutesError.outOfRange(value)
    }
    return value
}

do {
    print(try validatedMinutes(0))
} catch {
    // 此处 error 的类型是 MinutesError，不需要强转。
    switch error {
    case .outOfRange(let value): print("拒绝分钟：\(value)")
    }
}

完整可运行示例是 TypedThrows.swift，依次验证 25、0、181。网络、JSON 解码和任务取消可能产生不同错误；本课 decodePlan 需要保留 DecodingError 与 PlanError，因此继续使用普通 throws。不要为了采用新语法把不同故障强行压成同一种错误。

把清理注册在取得资源的附近

defer 在离开当前作用域时执行，无论通过正常返回还是抛错，多个 defer 按后注册先执行。它适合关闭文件、释放锁等同步清理；不是“稍后某个任意时间”或异步调度。本实验用 cleanup 回调让行为可以测试，不读写用户文件。编码 round trip 测试验证模型经 JSON 往返没有丢失数据；非法数据测试则验证业务规则。

public func withCleanup<Value>(
    _ operation: () throws -> Value,
    cleanup: () -> Void
) rethrows -> Value {
    defer { cleanup() }
    return try operation()
}

rethrows 表示该函数只有在传入闭包抛错时才会抛错。这里不需要提前掌握复杂错误抽象，先理解清理不会因中途 throw 而被漏掉。

验收现象

合法记录可编码往返；minutes=0 抛 PlanError.invalidMinutes(0)；{} 解成数组时抛 DecodingError；cleanup 在成功和抛错时均执行一次。 typed throws 实验接受 25，分别拒绝 0 和 181；改为普通 throws 后需重新设计 catch 中的类型处理。

let valid = Data(#"[{"title":"Swift","minutes":25,"isCompleted":false}]"#.utf8)

let encoded = try encodePlan(sessions)

从前端迁移时，留意这些误区

  • JSON 解析成功不代表可信业务数据。
  • init 参数默认值不等于 JSON 缺字段时的默认解码规则。
