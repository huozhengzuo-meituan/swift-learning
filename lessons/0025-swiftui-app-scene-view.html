从 App 到 View：声明式界面的边界

你已有组件化经验，本课把组件、应用入口和窗口生命周期对应到 SwiftUI；不要把 View 结构体当作持久的 DOM 节点。

前置：24 Swift 6 迁移与并发里程碑

本课的一个成果运行 NativeStudy，并用一个纯 View 描述学习条目的显示。

App 声明入口，Scene 声明窗口

NativeStudyApp 的 @main 是程序入口。它的 body 返回 some Scene，WindowGroup 内放根视图；系统管理窗口与场景的生命周期。一个 macOS 应用可以同时有多个窗口，不能把某一行列表的局部选择存为全局唯一变量。App 层适合建立依赖并注入，Scene 层决定窗口组织，View 层负责展示和交互。示例把持久化容器在 App 初始化时构建一次，并将初始化失败转换为界面，而不是静默创建空库。

@main
@MainActor
struct TinyApp: App {
    var body: some Scene {
        WindowGroup { WelcomeView() } // 系统管理窗口
    }
}

body 描述当前结果，不负责执行副作用

body 是计算属性，可因依赖变化重新求值。写法类似从 props/state 得到 UI，但没有一套可任意修改的 DOM；结构体实例可以被重复建立，框架根据身份关联状态。不要在 body 中插入数据库、启动网络或修改状态，否则重复求值会触发重复工作。示例用 Button 的 action 执行保存或状态变更，用 .task 启动与视图生命周期关联的异步工作。把“声明内容”与“响应事件”分开，是后面正确理解 SwiftUI 的基础。

@MainActor
struct WelcomeView: View {
    var body: some View {
        VStack(alignment: .leading) {
            Text("Native Study").font(.title)
            Text("每天练习一个具体技能")
        }
    }
}

some View 与 result builder

some View 表示编译器知道具体返回类型，调用者只依赖 View 协议。VStack 的构建闭包使用 result builder，把多个表达式和条件分支组合为一种视图结构；它不是把任意语句变成 UI。if 决定结构，ForEach 根据身份生成子视图。先把组合拆成小 View，再考虑抽象，不必为统一返回类型到处套 AnyView。示例的加载状态 switch 清楚地表达互斥界面，具体类型仍由编译器处理。

struct StatusLabel: View {
    let completed: Bool
    var body: some View {
        if completed {
            Label("Completed", systemImage: "checkmark.circle")
        } else {
            Label("In progress", systemImage: "circle")
        }
    }
}

从前端迁移时，留意这些误区

  • 不要把 View 值的构造等同于组件挂载。
  • 不要在声明内容时执行有持久副作用的操作。

即时自测

body 应主要描述界面，把插入记录等副作用放到明确操作入口。
