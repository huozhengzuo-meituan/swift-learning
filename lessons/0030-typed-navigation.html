导航：以数据描述目标和路径

原生导航不只是一条 URL：窗口、分栏选择、压栈路径和模态编辑分别有自己的状态。

前置：29 身份与列表：状态为什么会保留或重置

本课的一个成果在详情中增加一个有类型的练习目标，并验证分栏与窄屏返回行为。

导航目标用值表示

NavigationLink(value:) 发出一个 Hashable 值，navigationDestination(for:) 将该类型映射到具体界面。示例 DetailRoute 使用 enum 表达 layoutWorkshop 与 nativeBridge，比散落的字符串路由容易维护。目标注册要处于对应 NavigationStack 内；不要在临时、惰性列表行里注册全局目标，否则框架可能无法稳定发现它。导航数据应轻量，通常用稳定 ID，而不是把复杂可变对象塞满路径。

enum DetailRoute: Hashable {
    case layoutWorkshop
    case nativeBridge
}
NavigationLink("Layout workshop", value: DetailRoute.layoutWorkshop)
// 在栈内的稳定位置注册：
.navigationDestination(for: DetailRoute.self) { route in
    switch route {
    case .layoutWorkshop: LayoutWorkshopView()
    case .nativeBridge: NativeBridgeWorkshopView()
    }
}

路径状态和模态状态有不同用途

需要程序化返回或深链时，使用 @State var path: [Route] 并传给 NavigationStack(path:)；append 表示前进，removeLast 表示后退。sheet 则用于编辑等独立任务，取消意味着结束该模态任务，不应顺便改变导航路径。NativeStudy 的主详情由 selection 决定，详情中的实验室用栈导航，编辑器用 sheet。这三种状态各自对应一个清楚的用户动作。

@State private var path: [DetailRoute] = []
// 练习：替换详情列中的 NavigationStack 为受控版本。
NavigationStack(path: $path) {
    // 在栈内注册 navigationDestination 后：
    Button("布局练习") { path.append(.layoutWorkshop) }
}

同一数据模型，平台导航表现可以不同

NavigationSplitView 适合侧边栏加详情；宽屏 iPad 和 macOS 可以同时显示两列，iPhone 等窄空间会折叠为栈。列表 selection 需要匹配 NavigationLink 的值类型。不要只在 Mac 编译成功就声称 iPhone 返回手势已验证；至少在两种布局下运行选择、进入实验室、返回、删除当前项。选择被删除或筛掉后，显示明确的空详情，而非访问已失效模型。

NavigationSplitView {
    List(selection: $selection) {
        ForEach(visibleItems) { item in
            NavigationLink(value: item.id) { StudyRow(item: item) }
        }
    }
} detail: {
    NavigationStack { /* 当前选择的详情 */ }
}

动手：为详情增加一个“回忆练习”目标，使用枚举 case 注册，并在 iPhone 与 Mac 上走完返回流程。

  1. DetailRoute 增加 recall case。
  2. 在 Workshops 区添加 NavigationLink，并在 switch 中添加 Text 或独立 RecallView。
  3. 分别在 Mac 窗口和 iPhone 模拟器选择条目、进入练习、返回详情和列表。
验收现象

新目标无需字符串拼接；返回层级清楚；窄屏不会把编辑取消当成导航后退。

先独立完成，再展开参考解法

给现有 DetailRoute 增加 case recall，再为该 case 返回一个独立视图。若要程序化导航才进一步引入 path，避免同时维护两套真相。

case .recall:
    Text("不看笔记解释 State 与 Binding 的区别")
        .padding()
        .navigationTitle("回忆练习")

从前端迁移时，留意这些误区

  • 不要把模态编辑和压栈导航合并成同一个布尔值。
  • 不要只按 Mac 窗口表现推断 iPhone 导航正确。
