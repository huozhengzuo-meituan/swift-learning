Swift 基础 / 25 MIN

用类型表达数据：let、var 与数值转换

你熟悉 JavaScript 的值和 TypeScript 的类型；本课将它们迁移到 Swift 编译时检查，并用一个百分比错误验证差异。

前置：01 建立可重复运行的 Swift 开发环境

本课的一个成果编写不丢失小数的完成比例计算，并识别常量、变量和显式转换。

先说清会不会变，再说清是什么

let 声明初始化后不再重新赋值的绑定，var 允许更新。Swift 可以从初值推断类型，但类型一旦确定，后续不能赋成其他类型。var count = 2 并不是动态类型；它仍是 Int。日常优先使用 let，需要变更时再改 var，这让读代码的人能缩小需要追踪的状态范围。

let completed = 2       // 推断为 Int
var total: Int = 4       // 显式标注相同的类型
total += 1
let title = "Swift"      // String
let isReady = true       // Bool
// total = "5"          // 取消注释会出现编译错误

显式转换的位置就是算法的一部分

在 Swift 中 Int 除以 Int 的结果仍为整数。Double(completed / total) 看似返回 Double，但除法已经丢掉小数。应先转换操作数，再除法。不同具体数值类型通常不会自动转换；这种显式边界让精度变化可见。浮点数用于近似量，不能因类型检查通过就认为每个十进制小数都能精确表示。

public func completionRatio(completed: Int, total: Int) -> Double {
    guard total > 0 else { return 0 } // 空计划约定显示 0
    return Double(completed) / Double(total)
}
// completed=2, total=5 -> 0.4
// Double(2 / 5)       -> 0.0

类型可以阻止部分错误，契约仍要由你定义

类型系统知道 total 是整数，却不知道它表示多少个任务。本例把 total 非正数约定为零比例；这是一条显示层策略，不是所有产品都应采用的通用规则。未来若计数来自外部数据，应在输入边界验证 completed 和 total 的关系。先分清“编译失败”和“业务结果不符合需求”，能让你更准确地使用测试。

条件必须是 Bool，不能像 JavaScript 一样把 0、空字符串直接当成 false。if total > 0 表达清楚了判定；if total 不合法。查阅 Swift 语法速查 时，同时练习说出每个表达式的类型。

基础实验 02

swift run --package-path examples/SwiftFoundations foundation-lab 2

终端命令默认在 swift-learning 根目录执行；说明为 Xcode 操作时，跟随项目 README。

动手：找出“完成 1 项、总共 4 项，却显示 0”这一错误的原因并修复。

  1. 运行第 2 课，先预测 2/5 的结果。
  2. 在 Basics.swift 中临时把计算改成 Double(completed / total)，运行观察结果。
  3. 恢复先转换再除法；将 FoundationLab.swift 的 case 2 输入改为 1 和 4（注意移除 total += 1）。
  4. 运行 swift test --package-path examples/SwiftFoundations --filter ratio。
验收现象

原示例输出 0.4；修改后的 1/4 示例输出 0.25；ratio 测试通过。

先独立完成，再展开参考解法

替换函数体为下面完整实现。不要只转换整个除法表达式。演示输入的修改可以保留为自己的实验，也可恢复原来的 2 和 5。

public func completionRatio(completed: Int, total: Int) -> Double {
    guard total > 0 else { return 0 }
    return Double(completed) / Double(total)
}

从前端迁移时，留意这些误区

  • var 表示可变，不表示可随时更换类型。
  • 整数除法丢掉的小数无法靠事后转换恢复。

即时自测

Double(1 / 4) 的结果是 0.25。
