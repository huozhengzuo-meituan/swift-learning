Swift 基础 / 25 MIN

建立可重复运行的 Swift 开发环境

从你熟悉的构建工具切入，把一次成功运行拆成可解释、可复现的步骤。先掌握独立于 UI 的开发循环，后续再把相同业务逻辑接入 SwiftUI。

前置：无需 Swift 前置知识

本课的一个成果从工作区运行第一个 SwiftPM 示例，并解释编译器、语言模式、SDK 与最低系统版本。

四个版本，回答四个问题

Swift 编译器把源码转成机器码；Swift 语言模式决定哪些语言规则生效；Apple SDK 提供系统 API 的声明与构建资源；deployment target 决定应用声明支持的最低系统。它们不能互相替代。新编译器并不意味着程序只能运行在最新系统，选择 Swift 6 模式也不会自动获得新系统才提供的框架 API。

本包使用 swift-tools-version: 6.0、swiftLanguageModes: [.v6] 和 macOS 14 基线。tools version 是包清单可用能力和最低工具链要求；本机实际编译器要用命令核实。课程准备时本机是 Swift 6.4，不能把这个本机事实当作所有读者环境的前提。

一个包里的三个角色

打开 examples/SwiftFoundations/Package.swift。FoundationCore 是可被导入的库 target，保存纯业务模型和函数；FoundationLab 是 executable target，负责读参数和打印；测试 target 依赖库。product 是包向使用者提供的产物。它们与 npm package、源码目录有相似职责，但 Swift 的模块可见性由访问控制限定。

// Package.swift 中的真实依赖方向
.target(name: "FoundationCore"),
.executableTarget(name: "FoundationLab", dependencies: ["FoundationCore"]),
.testTarget(name: "FoundationCoreTests", dependencies: ["FoundationCore"])
// main 文件导入的是模块名，运行时选择的是产品名。
import FoundationCore

把编辑、构建、运行分开观察

所有课程命令都从 swift-learning 根目录执行。swift build 只构建，swift run 在需要时构建后运行，swift test 构建并执行测试。第一次较慢通常因为要编译依赖模块；后续增量构建较快。不要通过重建项目或升级 deployment target 来碰运气消除错误，先阅读第一条编译诊断。

# 在终端逐行执行
xcode-select -p
swift --version
swift build --package-path examples/SwiftFoundations
swift run --package-path examples/SwiftFoundations foundation-lab 1

本项目无第三方包依赖，语言实验无需访问外部服务。你可以在 Xcode 打开 Package.swift 阅读与调试；iOS App 的签名、模拟器与生命周期将在原生工程部分专门学习。

基础实验 01

swift run --package-path examples/SwiftFoundations foundation-lab 1

终端命令默认在 swift-learning 根目录执行；说明为 Xcode 操作时，跟随项目 README。

动手：完成一次可复现运行，并做一个可逆的编译失败实验。

  1. 在终端运行本课命令，记录 swift --version 的完整输出。
  2. 打开 FoundationLab.swift，找到 case 1，将第一条 print 文本改成自己的名字，保存并再次运行。
  3. 临时删除该 print 的右括号，运行 swift build，阅读第一条错误；恢复括号后重新构建。
  4. 口头指出 Package.swift 中的工具版本、语言模式和最低系统版本各在何处。
验收现象

第 1 课输出自定义问候；恢复源码后构建通过。能解释语法错误发生在编译阶段，而不是程序运行阶段。

从前端迁移时，留意这些误区

  • 不要把 Swift 6 当成 iOS 6，也不要把 SDK 版本当成最低系统版本。
  • @main 入口与 main.swift 顶层入口不能在同一个可执行模块中重复使用。
