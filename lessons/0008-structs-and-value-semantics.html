用结构体保护业务状态的边界

从 JavaScript 对象迁移时，最容易误判的是赋值后的共享关系。本课用可观察的行为建立值语义，而不是把它简化成内存布局口号。

前置：07 用闭包组成可读的数据转换

本课的一个成果创建一个可完成的学习任务，并用副本实验验证值语义。

结构体描述一份值，初始化建立完整状态

struct 可以拥有存储属性、计算属性、初始化器和方法。初始化结束前需要为所有存储属性提供值；这让实例创建后不处于“某个字段还没赋值”的半成品状态。定义显式 init 后，我们把可读的构造 API 作为公共边界。self.title 指向实例属性，右边的 title 是参数，用 self 可以解决同名歧义。

public struct StudySession: Equatable, Codable, Sendable {
    public let title: String
    public let minutes: Int
    public private(set) var isCompleted: Bool

    public init(title: String, minutes: Int, isCompleted: Bool = false) {
        self.title = title
        self.minutes = minutes
        self.isCompleted = isCompleted
    }
    public var label: String { "\(title) · \(minutes) 分钟" }
    public mutating func complete() { isCompleted = true }
}

把事实存起来，把显示值算出来

title、minutes、isCompleted 是独立事实，label 则能由事实推导，因此用计算属性。若把 label 也存一份，字段改动后容易忘记同步。private(set) 允许外部读取完成状态，但只能通过类型提供的方法修改；它与彻底 private 不同。mutating 声明方法会改变结构体自身，所以只能在可变实例上调用。

代码中的 Equatable 让值可比较，Codable 为第 13 课的数据编码准备，Sendable 为并发课程准备。本课先关注三种属性和 complete；不需要为了开始实验一次学完所有协议。可把协议理解为类型作出的能力承诺，下一阶段会逐个拆解。

复制后的行为是语义，不是复制成本的承诺

给结构体赋值会获得独立的值。本例所有存储属性都拥有值语义，修改副本不影响原值。标准集合常使用写时复制优化，但你不应依赖其内部实现。也不要推断“struct 永远深复制”：若结构体内部保存 class 实例，副本可能仍引用同一个对象。先判断属性组成，再判断是否存在共享状态。

let original = StudySession(title: "值语义", minutes: 25)
var copy = original
copy.complete()
print(original.isCompleted) // false
print(copy.isCompleted)     // true

先独立完成，再展开参考解法
let original = StudySession(title: "值语义", minutes: 25)
var copy = original
copy.complete()
#expect(!original.isCompleted)
#expect(copy.isCompleted)

测试应保留对原值的断言。如果只检查 copy 为 true，无法发现意外共享状态造成的回归。

从前端迁移时，留意这些误区

  • Swift struct 赋值与 JavaScript 对象赋值的共享行为不同。
  • 值语义不等于总在栈上，也不等于必须立即拷贝全部内存。
