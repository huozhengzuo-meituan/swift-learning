让 Mac 应用像一个 Mac 应用

共享业务代码不等于两个平台采用同一种交互。Mac 用户需要窗口、菜单和键盘操作。

前置：37 用 Xcode 解释一次卡顿与一次对象泄漏

本课的一个成果解释窗口状态与应用状态，并验证菜单命令作用于当前窗口。

Scene 表达应用结构

WindowGroup 定义一类窗口；在支持的平台上可以出现多个实例。Settings 是 macOS 设置场景。只把 iPhone 页面等比例放大，会丢失窗口恢复、菜单与多任务上下文。打开 NativeStudyApp，找到这两种 Scene，再运行 Mac scheme 观察应用菜单。

NativeStudy 的 StudyPreferences 在 App 层建立，因此多个窗口看到同一个会话偏好；列表的搜索和选中状态由各窗口视图持有。这个选择并非固定答案：如果你希望每个窗口独立筛选，就把筛选状态移到窗口级。

命令必须有目标

假设打开两个窗口，菜单“新建学习条目”应该作用于用户当前操作的窗口。把一个全局 Boolean 发给所有窗口会同时打开多个 sheet。样例借助 FocusedValue 提供当前窗口能力，再由 Commands 调用；当没有可执行目标时按钮禁用。

// NativeStudyApp 中的思路，完整代码见 Sources。
@FocusedValue(\.newStudyItem) private var newStudyItem

// CommandGroup 内：
Button("New Study Item") { newStudyItem?() }
    .keyboardShortcut("n", modifiers: [.command, .shift])
    .disabled(newStudyItem == nil)

快捷键应避免劫持系统常用操作。菜单不仅是另一个按钮位置，它还表达当前焦点可执行的动作。

设计一个双平台验收矩阵

Mac 验证 Tab 焦点、快捷键、窗口缩放和设置；iPhone 验证触摸目标、键盘遮挡和紧凑导航；iPad 再验分栏与大小变化。共用的数据约束应一致，但工具栏位置和导航呈现可不同。使用 #if os(macOS) 处理平台特有类型，使用 availability 判断同一平台的系统版本。

扩展练习可增加一个按条目 ID 打开的详情 WindowGroup。传递轻量 ID，在共享存储里找到实体，可以避免传递值副本导致两个窗口各改各的。窗口恢复时还需处理 ID 已删除的情况。

动手：验证新建菜单只影响当前窗口

  1. 运行 Mac scheme，用 File → New Window 创建第二个主窗口。
  2. 分别输入不同搜索条件，观察是否独立。
  3. 切换当前窗口，使用 ⌘⇧N；确认只在当前窗口出现编辑表单。
  4. 修改 Settings 的显示完成项选项，记录两个窗口的变化。
验收现象

窗口局部搜索独立；App 层会话偏好共享；新建动作由焦点窗口处理。

先独立完成，再展开参考解法

如果两个窗口都响应新建，检查是否使用了 App 层共享 sheet Boolean。保留每个窗口的 presentation 状态，把“发起新建”的闭包以 focused value 暴露给菜单。若偏好也要独立，将其所有者下移，而不是复制一套不会同步的引用。

从前端迁移时，留意这些误区

  • CSS 响应式布局经验不能代替原生平台交互习惯。
  • 编译条件 #if os 与运行时 #available 解决不同问题。

即时自测

在 App 中创建同一个引用对象并注入多个窗口，会共享该对象。

  • 同一条目在两个窗口展示，传副本还是 ID 更容易保持一致？
