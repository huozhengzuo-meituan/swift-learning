async / await：挂起、恢复与错误

先利用熟悉的 JavaScript async 直觉，再修正 Swift 对任务、隔离和错误的要求。

前置：12 看见引用共享，打断闭包保留环 · 14 里程碑：交付一个有行为测试的学习计划核心

本课的一个成果编写并运行一个可抛错的异步函数，准确解释 await 的含义。

把等待建模为函数效果

签名中的 async 表示函数允许挂起，throws 表示它可能抛错；二者是独立能力。调用写作 try await，正常结果仍然是 String，而不是需要手动展开的 Promise。源码中的 await 标出潜在挂起点，不承诺每次都会挂起，也不创建一个新的任务。先把本课看成“一个任务按顺序执行两步”，不要急着追求并行。

let name = try await loadName()
let count = try await loadUnreadCount()
// count 的调用在 name 返回后才开始。
print(name, count)

挂起任务与阻塞线程

示例 loadName 用 Task.sleep 模拟等待：挂起时运行时可以让线程处理别的任务。若你在 async 函数里做一个长时间同步循环，那个循环仍会占用当前执行器；仅添加 async 不会自动让计算离开主 actor。Web 中一个重型同步函数同样会影响交互，但 Swift 还需要明确状态属于哪个 actor。不要以打印线程编号作为正确性依据，应该依据隔离声明与数据关系推理。

public func loadName() async throws -> String {
    // 等待可被取消，不占着线程睡眠。
    try await Task.sleep(for: .milliseconds(2))
    return "林同学"
}

保留错误含义

运行示例后，把 loadName 暂时改成抛出自己的错误，再看调用方的 do/catch。不要使用 try? 把网络故障、取消和解析失败全部变为 nil，否则界面很难给出正确反馈。入口 main() async throws 适合小实验，让意外失败直接结束命令；真实页面会区分可重试错误与用户主动离开的取消。此处时间仅用于演示等待，不是性能基准。

do {
    print(try await loadName())
} catch is CancellationError {
    print("任务已取消")
} catch {
    print("加载失败：\(error)")
}

验收现象

依次获得 林同学 和 3；第一个调用抛错会跳过余下正常路径。

先独立完成，再展开参考解法

解法是保留两个独立的 let，并在每个调用前写 try await。第二个语句依赖控制流到达它，而非依赖第一个结果的类型。取消 Task.sleep 会抛错，因此应进入 catch，不能把它解释为“没有名字”。

let name = try await loadName()
let count = try await loadUnreadCount()
print("顺序加载：", name, count)

从前端迁移时，留意这些误区

  • 把 Swift async 当作后台线程开关。
  • 用 try? 抹掉所有失败路径。

即时自测

给一个函数加上 async，就能保证它的同步计算不会占用 MainActor。
