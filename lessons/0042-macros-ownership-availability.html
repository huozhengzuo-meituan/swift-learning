读懂宏、所有权与版本边界

这一课建立阅读现代 Swift 代码的能力。自定义编译器插件与高性能所有权设计可在主线之后深入。

前置：41 从本地构建走到可交付版本

本课的一个成果展开一个系统宏，并用编译器观察不可复制值被消耗后的行为。

宏在编译时生成代码

@Observable、@Model 和 #Preview 都不是普通运行时函数。宏在编译阶段展开为 Swift 代码，再接受检查。在 Xcode 对宏调用选择 Expand Macro，可以看到观察访问器或模型支持代码；理解生成结果比死记“加个注解就好了”更可靠。

宏不是任意文本替换，也不等于属性包装器。@State 是属性包装器，@Observable 是 attached macro；它们可以共同出现但负责不同事。构建自己的宏需要独立实现 target 与 SwiftSyntax，本课程先学会使用和调试系统宏。

值语义之外，还有是否允许复制

大多数普通值可复制。~Copyable 表示一个类型不承诺可复制，适合表达某些独占资源的生命周期。borrowing 参数允许读取而不消耗所有权，consuming 消耗调用方的值，inout 则提供独占修改访问。这不是 TypeScript readonly 的另一种拼写。

struct ExportTicket: ~Copyable {
    let filename: String
    borrowing func preview() -> String { filename }
    consuming func finish() { print(filename) }
}

先运行 Ownership.swift，再在 finish 后取消注释 preview 的调用；编译器会拒绝消耗后的再次使用。示例不接触真实文件，只演示语言规则。普通业务模型不应仅为“高级”而改成不可复制类型。

三种版本判断不要混为一谈

#if compiler(>=6.2) 判断编译器能否理解某些语法；#if os(macOS) 处理平台类型；if #available(iOS 18, macOS 15, *) 保护运行时 API 使用。Deployment Target 设定最低系统版本，SDK 决定编译时看到哪些声明。

Swift 6.2 引入的默认隔离等能力还受项目设置影响。读新示例先查 proposal 的实现版本、当前编译器以及 feature flag，再决定是否迁入本课程 Swift 6.0 基线项目。新编译器支持旧 API，不会让旧系统获得新 API。

不可复制值实验

swift -swift-version 6 examples/PlatformRecipes/Ownership.swift

终端命令默认在 swift-learning 根目录执行；说明为 Xcode 操作时，跟随项目 README。

动手：让编译器拒绝一次非法重复使用

  1. 运行 Ownership.swift 并预测两行输出。
  2. 在 consuming finish 后取消注释 preview 调用，运行并阅读诊断。
  3. 恢复合法版本，再对 NativeStudy 的 @Observable 选择 Expand Macro。
  4. 说出宏新增的一种支持能力，以及它没有替你处理的一种业务责任。
验收现象

合法程序运行；非法版本无法编译；能够解释失败来自所有权而不是线程问题。

先独立完成，再展开参考解法

finish 消耗 ticket 后，原变量不能再次读取；把只读 preview 移到 finish 之前，或重新创建一个新 ticket。@Observable 生成观察支持，不会生成保存策略或 MainActor 隔离。不要通过复制、强转或不安全标记绕过生命周期约束。

从前端迁移时，留意这些误区

  • ~Copyable 不等于线程安全；Sendable 也不等于值不可变。
  • 不要为了使用新关键字而增加无收益的复杂度。

即时自测

@Observable 会自动替模型加入业务校验和数据库持久化。
