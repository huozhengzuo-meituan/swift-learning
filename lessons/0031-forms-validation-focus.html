本课的一个成果实现“合法才保存、失败保留草稿、取消不污染模型”的编辑体验。

验证规则应成为可测试的逻辑

StudyDraft.normalizedTitle 去除首尾空白，isValid 检查 1 至 80 个 Swift Character。String.count 不是 UTF-8 字节数，也不能随意替换为 JavaScript UTF-16 长度。按钮 disabled 改善用户体验，但 StudyWriter.save 仍必须 guard 验证，因为其他调用入口可能绕过 UI。此处只清理标题，不擅自截断用户笔记，避免保存时无声丢失内容。

struct StudyDraft: Equatable, Sendable {
    var title = ""
    var notes = ""
    var normalizedTitle: String {
        title.trimmingCharacters(in: .whitespacesAndNewlines)
    }
    var isValid: Bool { (1...80).contains(normalizedTitle.count) }
}

焦点是一份明确的交互状态

@FocusState 表达哪个字段持有焦点；单字段可用 Bool，多字段用可选 enum 更清楚。focused 把原生焦点系统与状态连接，设为 false 或 nil 可解除焦点。不要靠多次延时强抢焦点掩盖生命周期问题；示例在表单 .task 中请求初始焦点。submitLabel 只描述键盘操作含义，onSubmit 才承接事件，保存前仍检查有效性。

@FocusState private var titleIsFocused: Bool
TextField("Title", text: $draft.title, axis: .vertical)
    .focused($titleIsFocused)
    .submitLabel(.done)
    .onSubmit { if draft.isValid { save() } }
// 表单容器：.task { titleIsFocused = true }

成功才结束编辑，失败提供重试机会

保存先调用 writer，再通知父视图选择新记录，最后 dismiss。顺序很重要：若先关 sheet 再异步发现失败，用户可能丢失草稿且不知道发生什么。错误用可读提示展示，草稿留在 State 里方便修正或重试。macOS 为默认操作和取消绑定系统快捷键；iOS 验证软键盘遮挡、长笔记滚动与中文组合输入。不要把所有平台的输入问题都归结为布局高度。

private func save() {
    do {
        let saved = try StudyWriter.save(draft, editing: item, in: context)
        onSave(saved.id)
        dismiss() // 成功提交后才结束模态任务。
    } catch {
        errorMessage = error.localizedDescription
    }
}

动手：验证表单的边界输入与取消行为，并扩展为标题、笔记两个焦点。

  1. 输入纯空格、80 个 emoji、81 个 emoji，观察保存按钮。
  2. 在 Tests/NativeStudyTests.swift 找到对应边界测试并运行 ⌘U。

验收现象

纯空白与 81 字符标题不可提交；80 个复合 emoji 可提交；焦点切换不会丢失草稿。

  • 不要用多个控件共享同一个焦点 enum 值。
