前置：39 把 UIKit / AppKit 控件接入 SwiftUI

本课的一个成果完成一个会报告错误的 JSON 导入，并说明不同数据的存储边界。

先为数据分类

开关与排序偏好可以使用 UserDefaults / AppStorage；业务实体适合 SwiftData 或明确设计的文件格式；少量密码、令牌等秘密应使用 Keychain。任何客户端内置密钥都无法靠改文件名变安全。当前 NativeStudy 的偏好只保留在会话内，学习条目用 SwiftData。

失败路径必须进入设计：磁盘不可写、JSON 损坏、旧版 schema、用户撤销授权。导入前先完整解码并验证，再开始更改业务状态；不能已经写入一半才发现后半段格式错误。

系统文件选择器交付的是一种授权

fileImporter 让用户选择支持类型的文件。系统返回 security-scoped URL 时，读取期间调用 startAccessingSecurityScopedResource，并在成功取得权限后成对 stop。defer 适合表达“无论成功或抛错都释放”。权限失败最终必须可观察，不能静默显示导入成功。

let url = try result.get()
let didStart = url.startAccessingSecurityScopedResource()
defer { if didStart { url.stopAccessingSecurityScopedResource() } }
let data = try Data(contentsOf: url)
let items = try JSONDecoder().decode([ImportedItem].self, from: data)

补充实验同步读取小文件，只为观察授权和解码。正式产品需限制大小，并把 I/O 放到明确的工作边界，支持取消。不要在 MainActor 上读取任意体积的外部文件。

隐私声明跟随实际使用

PrivacyInfo.xcprivacy 声明数据收集与 required reason APIs 使用。只写“我们不收集”不能替代对 API 的检查；如果新增 UserDefaults 等相关调用，应按真实用途查看当前 Apple 允许的理由。摄像头等受保护资源还可能涉及用途描述、capability 与用户授权，这是不同配置层。

对学习项目先建立数据清单：条目标题在哪里保存、是否出设备、日志是否包含内容、哪些 SDK 参与。课程示例没有远程后端；以后接入服务时要重新检查，不能沿用离线项目的结论。

验收现象

成功时显示已验证条数；失败时展示原因；关闭文件后不继续持有不必要授权。

先独立完成，再展开参考解法

使用 Result.get 把选择失败纳入 do/catch；解码成功后才更新成功状态。对每个成功的 start 安排 defer stop。大文件增加大小限制和可取消 I/O 服务，再把解码结果以值跨隔离边界交给 UI。Secrets 使用 Keychain 并处理 OSStatus，不写进 UserDefaults。

从前端迁移时，留意这些误区

  • 沙盒内可访问不等于所有外部路径都可直接读取。
  • 加密传输不意味着可以把令牌打印到日志。

即时自测

把访问令牌写进 UserDefaults，等价于保存在 Keychain。
