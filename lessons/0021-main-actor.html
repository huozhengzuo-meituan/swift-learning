Swift 6 与并发 / 30 MIN

MainActor：UI 状态、重入与默认隔离

主 actor 约束状态访问；请求先后与页面生命周期仍由你建模。

前置：20 Sendable、@Sendable 与 sending

本课的一个成果把界面状态显式隔离到 MainActor，并避免旧请求覆盖新结果。

先显式声明 UI 边界

ProfileScreenModel 用 @MainActor 标注整个类型，phase、revision 与 load 的访问保持在主 actor。即使 fetch 在别处等待，方法恢复后仍在声明的 actor 上更新状态。这里不引入 SwiftUI Observation，先学习并发契约；后续再决定如何让 View 观察 phase。不要把 DispatchQueue.main.async 当成每个状态赋值旁的补丁，类型级隔离更容易被编译器检查。

@MainActor
final class ProfileScreenModel {
    enum Phase { case idle, loading, loaded(ReaderProfile), failed(String) }
    private(set) var phase: Phase = .idle
    private var revision: UInt = 0
}

主 actor 也会重入

同一个页面可能先请求 A，再请求 B。A 挂起时 B 开始并先返回；若 A 后返回直接写 phase，用户会看到过时信息。示例每次 load 递增 revision，开始时保存本次值，在 await 后确认仍等于当前值才发布。取消可以减少无用工作，版本号保护仍然必要，因为旧服务不一定响应取消。测试使用门闩让旧请求最后完成，明确验证新结果保持不变。

revision &+= 1
let requestRevision = revision
phase = .loading
let profile = try await fetch()
try Task.checkCancellation()
guard revision == requestRevision else { return }
phase = .loaded(profile)

不要猜 Xcode 的默认值

本包使用 swift-tools-version 6.0 和 .v6，未配置默认 MainActor，也未打开 upcoming flags，因此需要显式 @MainActor。Swift 6.2 起，工具链支持为 target 设置默认 actor 隔离；SwiftPM 的 .defaultIsolation(MainActor.self) 需要 6.2 的 manifest API。它与 Swift 6 语言模式是不同维度。查看你真实项目的 Build Settings，不能因为安装了新 Xcode 就假设所有方法都自动属于主 actor。

验收现象

最后保持 id 为 2 的新结果，即使 id 为 1 的旧结果最后返回。

先独立完成，再展开参考解法

版本号必须在 await 之前捕获，且成功、取消、失败三个分支都应验证版本。只保护成功分支仍可能让旧请求的失败信息覆盖新页面。当前实现已覆盖这三条写入路径。

从前端迁移时，留意这些误区

  • 认为 MainActor 会自动处理请求竞态。
  • 把 Swift 6 语言模式和默认 MainActor 设置当作同一个开关。

即时自测

界面模型加上 @MainActor 后，旧请求就不可能覆盖新请求的结果。
