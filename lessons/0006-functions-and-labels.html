Swift 基础 / 25 MIN

写出调用点清晰的函数

函数不仅是复用代码的容器，也是调用者读得最多的界面。本课从调用语句反推 API 的命名与副作用。

前置：05 把“可能没有值”变成必须处理的分支

本课的一个成果用参数标签、默认值与 inout 清楚表达输入和修改行为。

外部标签服务调用者，内部名字服务实现者

Swift 参数通常拥有调用标签和函数体内名字。for minutes 中 for 用于调用，minutes 用于实现；_ title 表示调用处省略标签。一个名字并非越短越好，schedule("Swift", for: 25) 能让读者直接理解数字的角色。API 设计优先考虑调用点的清晰，而不是把所有参数都用下划线压短。

public func schedule(_ title: String, for minutes: Int = 25) -> String {
    "\(title)：\(minutes) 分钟"
}
print(schedule("Swift"))           // 使用默认 25
print(schedule("SwiftUI", for: 40))

返回值通常比隐藏修改更容易推理

普通函数参数默认不可重新赋值。函数可以返回一个值，也可以返回元组，将几个紧密相关的结果放在一起，例如 (completed: Int, total: Int)。无返回值的函数返回 Void。只有一个表达式的函数可以省略 return；初学时显式写 return 也完全合理，不必为了简短牺牲理解。

func progressText(completed: Int, total: Int) -> String {
    return "\(completed)/\(total)"
}
let format: (Int, Int) -> String = progressText
print(format(2, 5)) // 函数类型本身不携带调用标签

inout 把修改权限写进调用点

inout 允许函数修改调用者的变量，调用时必须加 &。它不等同于把 JavaScript 对象引用传入；Swift 对同一存储的重叠读写有独占访问规则。不要在同一次调用中把同一个变量交给两个会重叠访问的 inout 参数，也不要把 inout 当作可长期保存的引用。调用结束后能看到修改，但函数不拥有那个变量。

public func add(_ minutes: Int, to total: inout Int) {
    total += minutes
}
var total = 10
add(25, to: &total) // 调用点明确标记变更
print(total)       // 35

验收现象

schedule 默认输出 Swift：25 分钟；add 更新后的 total 为 35；常量不能传给 inout。

先独立完成，再展开参考解法
public func schedule(_ title: String, for minutes: Int = 25) -> String {
    return "\(title)：\(minutes) 分钟"
}
public func add(_ minutes: Int, to total: inout Int) {
    total += minutes
}
var total = 10
add(25, to: &total)

若无需原地更新，也可选择返回 total + minutes。是否使用 inout 取决于调用者是否应该看到明确的变更语义。

从前端迁移时，留意这些误区

  • Swift 函数参数不是可随意重赋的局部 var。
  • inout 不是可以跨异步任务保存的引用。

即时自测

带 inout 的参数可以接受 let 常量，只要函数内没有真的修改。
