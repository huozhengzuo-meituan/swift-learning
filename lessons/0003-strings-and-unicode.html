按用户看到的字符处理 Unicode 文本

原生界面会遇到中文、重音字母、emoji 和多语言输入。先明确你正在数的是字符、编码单元还是字节，才能正确处理它们。

本课的一个成果生成不会截断组合 emoji 的标题预览。

一个看得见的符号可能由多个标量组成

Swift 的 Character 表示扩展字素簇，接近用户感知的一个字符。String 是 Character 集合；UTF-8 和 UTF-16 是编码视图。👩🏽‍💻 含人物、肤色修饰和连接序列，String.count 计为一个，而 utf16.count 会更大。因此你从 Web 迁移的字符串长度直觉需要校准，不能把服务端字节限制和 UI 字数限制混为一谈。

let title = "👩🏽‍💻学习Swift"
print(title.count)        // 8 个 Character
print(title.utf16.count)  // 14 个 UTF-16 码元
print("预览：\(title)")   // 插值，不是 ${title}

用集合操作表达截取意图

String 不接受整数下标，因为定位第 n 个 Character 可能需要遍历。对“取前几个字符”的需求，直接使用 prefix，比手算编码位置更可靠。prefix 返回 Substring，短期切片可以共享原存储；要长期保存小片段时转换成 String。本例先把负数长度归零，避免把调用错误变成运行时陷阱。

public func preview(_ title: String, limit: Int) -> String {
    let limit = max(0, limit)
    return title.count <= limit
        ? title
        : String(title.prefix(limit)) + "…"
}
// preview("👩🏽‍💻学习Swift", limit: 3) -> "👩🏽‍💻学习…"

索引必须来自当前字符串

需要访问具体位置时，用 startIndex、index(after:) 等产生 String.Index；不要把另一个字符串的索引直接拿来用。修改字符串后，先前保存的索引也可能失效。String.count 需要识别字符边界，不应假定是常数时间；本课的小标题无需提前优化，但对大文档应避免在循环里重复计算长度。

一个优秀的 UI 截断测试应包括纯英文、中文、组合 emoji、空字符串和刚好不需要截断的边界。只测试 ASCII 会让错误隐藏到真实用户输入出现时。此处预览适合学习文本处理，真正的 SwiftUI 单行视觉省略应优先由 Text 的布局能力处理。

先独立完成，再展开参考解法

本课完整实现就在 preview。断言应比较实际文本，而不是只比较长度；这样同时验证没有切碎 emoji 和省略号策略。

#expect(preview("👩🏽‍💻学习", limit: 1) == "👩🏽‍💻…")
#expect(preview("学习", limit: 2) == "学习")
#expect(preview("", limit: 1) == "")

从前端迁移时，留意这些误区

  • Swift 的 count 不等同于 JavaScript 的 string.length。
  • 不要为视觉省略主动破坏原始文本；存储完整内容，展示时选择策略。
