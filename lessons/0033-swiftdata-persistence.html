SwiftData：模型、查询和保存失败

SwiftData 负责持久化和对象追踪，不是浏览器 localStorage 的语法替换；模型、容器、context 与查询各有职责。

前置：32 视图任务：加载、取消与过期结果

本课的一个成果完成学习条目的增删改查，并解释显式保存与内存预览的边界。

Model 描述结构，Container 配置存储

@Model 将类变成 SwiftData 可追踪模型；@Attribute(.unique) 给 id 添加唯一约束。ModelContainer 根据模型类型建立 schema 并配置底层存储。NativeStudy 禁用 CloudKit，使用本地持久库，不需要开发者账户或网络。初始化可能失败，示例显示存储错误而不是删除现有文件或偷偷切换内存库。模型结构演进要设计迁移，不能把“改了属性还能编译”当作兼容旧数据库的证明。

@Model
final class StudyItem {
    @Attribute(.unique) var id: UUID
    var title: String
    var notes: String
    var isCompleted: Bool
    var createdAt: Date
    // 完整初始化器见 StudyItem.swift。
}

Context 管理改动，Query 为界面取数据

@Environment(\.modelContext) 取得由上层容器提供的 context；@Query(sort:) 获取排序结果并随模型变化刷新界面。插入、属性修改、删除都先发生在 context 的追踪范围内。示例关闭 autosave，要求每个明确的用户动作显式 try save；这使成功与错误反馈更容易教学和验证。实际工程可以选择自动保存，但不能因此忽略错误、事务边界或用户以为已经保存的时点。

@Environment(\.modelContext) private var context
@Query(sort: \StudyItem.createdAt, order: .reverse)
private var items: [StudyItem]

let item = StudyItem(title: "SwiftData")
context.insert(item)
if context.hasChanges { try context.save() }

保存失败回滚，预览和测试使用独立存储

StudyWriter 捕获保存错误后 rollback，再把错误抛给 UI。该回滚影响 context 内全部未提交改动，因此示例坚持 UI 只编辑草稿、保存操作同步完成；复杂协作编辑需要更细的 context 边界。预览用 isStoredInMemoryOnly，避免在看界面时污染真实学习记录；单元测试也用独立容器。Model 对象不要跨 actor 随意传递，跨边界传稳定 ID 或 Sendable 快照，后台数据库工作另行设计隔离。

do {
    if context.hasChanges { try context.save() }
} catch {
    context.rollback()
    throw error
}
// Preview / tests:
let config = ModelConfiguration(isStoredInMemoryOnly: true,
                                cloudKitDatabase: .none)
let container = try ModelContainer(for: StudyItem.self,
                                   configurations: config)

编辑器打开期间，另一窗口可能删除该条目。保存还要验证原对象仍属于当前 context 且未被删除；否则应报错并保留草稿，不能跳过 save 却通知用户成功。
