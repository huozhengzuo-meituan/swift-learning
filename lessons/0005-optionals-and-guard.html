把“可能没有值”变成必须处理的分支

Optional 不是给类型系统添麻烦。它把“没有输入”和“转换失败”带进函数签名，使 UI 不必依赖运气才能运行。

前置：04 选择集合并用控制流统计主题

本课的一个成果将可空文本安全转换成 1 到 180 之间的学习分钟数。

T? 是两种可能，不是 T 的别名

Int? 表示“有一个 Int”或“没有值”。它与 Int 不同，不能未经检查直接参加需要 Int 的运算。Int("25") 得到可选值，是因为 Int("abc") 可能失败。nil 不是空字符串，也不是零；这些分别是 String、Int 中完全合法的值。和 TypeScript 的可空联合类型相比，你会看到类似的收窄思路，但 Swift 把解包机制直接纳入语言。

let text: String? = "25"
if let text, let minutes = Int(text) {
    print(minutes + 5) // 分支内 minutes 的类型是 Int
} else {
    print("请输入数字")
}

guard 让失败路径先退出

guard 的 else 必须离开当前作用域，例如 return 或 throw；成功解包的变量因此能在后续使用。表单校验常常适合这个形状：先排除无输入，再排除格式错误，再排除范围不合法。本例将三条条件放在一个 guard，是因为它们共享同一失败结果；若 UI 需要不同错误文案，应把结果升级成带原因的类型。

public func parseMinutes(_ input: String?) -> Int? {
    guard let input,
          let minutes = Int(input.trimmingCharacters(in: .whitespacesAndNewlines)),
          (1...180).contains(minutes) else { return nil }
    return minutes
}

默认值与强制解包都隐含产品决策

value ?? 25 表示缺失时取 25，并不会验证已有值。可选链 text?.count 在 text 缺失时保持 nil。! 则宣称值必然存在，宣称失败会终止执行；不能把它当成消除编译错误的快捷键。原生输入通常来自用户或网络，边界代码尤其应保留失败分支。

本实验把无效输入归并为 nil，因此它适合“能否提交”的简单判断。如果稍后需求要区分“必填”“格式不对”“超过上限”，不要到处添加布尔值；第 9 课会用枚举把状态与数据放在一起。

验收现象

" 25 " 与 "180" 返回对应整数；nil、"0"、"181"、"abc" 返回 nil。

先独立完成，再展开参考解法
public func parseMinutes(_ input: String?) -> Int? {
    guard let input else { return nil }
    let cleaned = input.trimmingCharacters(in: .whitespacesAndNewlines)
    guard let minutes = Int(cleaned) else { return nil }
    guard (1...180).contains(minutes) else { return nil }
    return minutes
}

这是与仓库实现等价、拆成三步的完整版本。逐步 guard 有利于初学时调试；熟悉后可以合并共享失败路径。

从前端迁移时，留意这些误区

  • 不要把 ! 当成 TypeScript 中只影响类型检查的非空断言；Swift 的 ! 有运行时后果。
  • ?? 是默认值策略，不是输入合法性验证。
