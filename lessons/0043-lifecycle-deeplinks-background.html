处理生命周期、深链接与后台边界

应用不是永远开着的页面。系统可能暂停、重建或终止进程，用户也可能从外部链接直接进入详情。

前置：42 读懂宏、所有权与版本边界

本课的一个成果解析一个外部条目链接，并解释 App 进入后台后哪些工作仍有保证。

页面、场景与进程不是同一生命周期

SwiftUI task 通常跟随视图身份与生命周期；ScenePhase 表达场景 active、inactive、background 等状态；进程是否仍存在由系统管理。把重要草稿等到“应用一定要退出时”再保存，会依赖一个并不可靠的时机。

View 中读取 scenePhase 反映其所属场景；App 层观察可能反映所有场景的汇总情况。Mac 多窗口中，一个窗口失去焦点并不说明整个 App 可以清空共享状态。

把 URL 变成可验证的路由值

外部输入先校验 scheme、host 与 ID，再查当前数据库。不能只要字符串包含 item 就进入页面，也不能假定链接指向的记录仍存在。热启动和冷启动都要走相同解析逻辑；冷启动时等依赖初始化后再呈现目的地。

guard url.scheme == "nativestudy", url.host == "item",
      let id = UUID(uuidString: url.lastPathComponent) else {
    // 显示可理解的无效链接状态
    return
}
// 按 id 查库；若记录已删除，显示不存在页面。

onOpenURL 负责接收已交付的链接。自定义 scheme 需注册 URL Types；Universal Links 还需域名关联配置。本课片段只做解析，不能仅加入回调就认为系统配置已经完成。

并发任务不等于后台执行资格

Task、Task.detached 都不会授予无限后台时间。后台下载、内容刷新和长任务有不同系统机制；BGTaskScheduler 等机制受系统调度，不能承诺每隔五分钟精确执行。先根据用户价值选择能力，再处理到期取消、状态保存与恢复。

通知和 WidgetKit 是后续专项。不要为了学习异步而一开始就申请多种后台权限。先把离开页面取消、回到前台刷新、记录恢复三件事做对，再连接系统服务。

验收现象

解析器只接收符合规则的 ID；能把 URL 配置、解析、查库与导航四步分开验收。

先独立完成，再展开参考解法

合法格式是 nativestudy://item/<UUID>。但合法 UUID 不证明有该数据。收到链接后先保存待处理路由，待数据库准备好再查询；找不到时显示不存在。ScenePhase 变化只触发短小可恢复工作，不启动永不结束的 detached 循环。

从前端迁移时，留意这些误区

  • 不要把浏览器 tab 隐藏事件与原生应用后台行为一一对应。
  • 自定义 scheme 的存在不证明调用者身份可信。

即时自测

Task.detached 可以让 iOS 应用不受限制地在后台持续运行。
