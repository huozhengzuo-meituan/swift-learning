状态归属表

写法职责典型位置
@State视图身份关联的局部状态，也可拥有 Observable 对象草稿、sheet 状态、页面模型所有者。
@Binding传递对已有真值的读写访问子编辑器修改父级草稿。
@Observable宏生成观察能力模型 class；不等于持久化或并发隔离。
@Bindable从 Observable 对象创建属性 BindingForm 中 Toggle/TextField 所需 $model.property。
@Environment(Type.self)从祖先环境获取模型/依赖App 注入的偏好；Preview 也要注入。
@Query按条件查询 SwiftData 持久实体列表；数据库容器需由环境提供。
@Environment(\.modelContext)获取当前 SwiftData 上下文保存、删除与查询边界。
@AppStorageUserDefaults 支持的轻量偏好不是秘密存储或业务数据库；检查所用 API 的隐私声明。

编辑页的数据流

实体 → 创建草稿 → 编辑局部状态 → 校验 → 保存 → 成功关闭

取消 → 丢弃草稿；失败 → 保留草稿 + 可重试错误；实体已删除 → 明确错误。

直接把持久实体所有属性绑定到编辑器，往往使“取消”失去含义。草稿通常用 struct；保存成功再应用到实体。共享上下文 rollback 会影响该上下文尚未保存的其它改动，复杂多窗口事务需要进一步隔离。

阅读旧工程时

ObservableObject、@Published、@StateObject、@ObservedObject 仍会出现在旧部署目标或现有架构中。新主线使用 Observation，不代表旧 API 必须立即重写。迁移时先确认支持系统，再逐一替换所有者和依赖；不要把 @StateObject 与 @Bindable 简单一对一替换。
