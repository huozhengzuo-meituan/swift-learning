需要工具生命周期与风险
顺序依赖try await后一项依赖前一项结果；不自动并行。
固定数量的独立工作async let结构化子任务，离开作用域前收束。
动态数量的独立工作TaskGroup / ThrowingTaskGroup完成顺序不等于输入顺序；必要时附带索引。
页面关联工作.task / .task(id:)跟随视图；取消需函数合作。
从同步入口启动异步Task { }非结构化任务；明确谁持有和取消。
共享可变后台状态actor同一隔离片段串行；await 前后检查不变量。
UI 状态@MainActor主 actor 上避免大量同步 CPU / I/O。
跨边界数据Sendable 值、ID、明确的 sending 转移不随意添加 @unchecked Sendable。

一个 actor 仍可能发生逻辑竞争

  1. 检查还有一个名额。
  2. await 请求付款；当前方法挂起。
  3. 另一个任务也看到最后一个名额。
  4. 两次付款完成，业务超卖。

actor 防护内存访问，不会把横跨 await 的事务变成原子操作。可在 await 前预留名额，失败/取消时释放；或恢复后校验版本。第 19 课有可运行的预留方案与确定性测试。

取消的检查顺序

do {
    try Task.checkCancellation()
    let value = try await fetch()
    try Task.checkCancellation()
    // 如果存在多个竞争请求，再检查 requestID 是否仍是最新。
    state = .loaded(value)
} catch is CancellationError {
    // 正常生命周期事件；通常不向用户展示“网络错误”。
} catch {
    // 某些 API 的取消使用自己的错误类型，同时检查任务取消状态。
    guard !Task.isCancelled else { return }
    state = .failed(error.localizedDescription)
}

以上是示意片段，fetch/state 需由具体模型提供；完整实现看 ConcurrencyLab。
