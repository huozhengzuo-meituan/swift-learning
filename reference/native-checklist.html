界面交付前

  • 按钮有可读目的，状态变化可被辅助功能理解，不只依赖颜色。
  • 最大字体下主要路径可完成；文本没有固定高度裁剪；系统控件优先保留语义。
  • 中文、英文、长文本和空值都走一遍；日期、数量采用本地化格式，不拼接句子片段。
  • Mac 用键盘可完成主要操作；iOS 键盘出现后仍能操作表单；中文输入组合态不被覆盖。
  • 错误提示说明发生了什么和可采取的动作；取消不会变成失败警报。

数据与边界

  • 外部输入先解析与校验；HTTP 状态错误不当作正常 JSON 成功。
  • 新上下文读回、应用重启和旧数据升级分开验证。
  • 保存失败不显示成功；已有存储打不开时不偷偷删库或换成内存模式。
  • 数据是否离开设备、日志内容、秘密存储位置、权限用途与隐私清单均与实际实现一致。
  • 外部文件授权成对释放；大文件 I/O 不阻塞主 actor；深链接先验证再路由。

代码评审的六个问题

  1. 这个状态属于值、对象、actor、窗口还是应用？
  2. 每个 await 前后的业务不变量是什么？
  3. 取消、失败和重试如何改变状态？
  4. 哪些测试能够在错误实现下失败？
  5. 这个 API 在最低部署系统可用吗？
  6. 实际验证覆盖什么，尚未验证什么？
